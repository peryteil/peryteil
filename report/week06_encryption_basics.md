# 🔐 자료보호와 암호화 기술의 원리

## 1. 정보보호(Information Security)의 3대 요소

정보보호는 데이터와 시스템의 안전성을 확보하기 위해 다음 세 가지 요소를 기반으로 설계된다:

| 보안 요소 | 정의 | 목적 |
|-----------|------|------|
| **기밀성 (Confidentiality)** | 인가되지 않은 사용자가 정보에 접근하지 못하도록 제한 | 데이터 유출 방지 |
| **무결성 (Integrity)** | 정보가 인가되지 않은 방식으로 변경되거나 손상되지 않도록 보장 | 위변조 방지 |
| **가용성 (Availability)** | 인가된 사용자가 필요한 시점에 정보에 접근 가능하도록 보장 | 시스템 운영 지속성 확보 |

---

## 2. 암호화(Encryption)의 개요

암호화는 데이터를 **암호문(Ciphertext)**으로 변환하여 **비인가자의 접근으로부터 보호**하는 기술이다. 암호문은 **복호화(Decryption)** 과정을 거쳐 원래의 평문(Plaintext)으로 복원할 수 있다.

암호화는 정보의 **기밀성**과 **무결성**, **인증(Authentication)**을 달성하기 위한 핵심 기술 중 하나이다.

---

## 3. 암호화 기법의 분류

### 3.1. 대칭키 암호화 (Symmetric Key Encryption)

- **하나의 키(K)를 공유**하여 암호화와 복호화 모두 수행
- 송신자와 수신자가 **동일한 비밀키를 사전에 공유**해야 함
- **고속 처리 가능**, 데이터량이 많은 경우 적합
- **단점**: 키 분배 및 관리가 어려움

#### ✅ 대표 알고리즘:
- AES (Advanced Encryption Standard)
- DES (Data Encryption Standard)
- RC4, Blowfish

#### ✅ 사용 사례:
- VPN 통신, 파일 암호화, TLS 세션 암호화

---

### 3.2. 비대칭키 암호화 (Asymmetric Key Encryption)

- **서로 다른 두 개의 키(Public Key / Private Key)**를 사용
- 공개키로 암호화 → 개인키로 복호화, 또는 그 반대
- **키 분배 문제 해결**, **디지털 서명** 및 **인증서 기반 통신**에 적합
- **처리 속도 느림**, 일반적으로 대칭키보다 연산량 큼

#### ✅ 대표 알고리즘:
- RSA (Rivest–Shamir–Adleman)
- ECC (Elliptic Curve Cryptography)
- DSA (Digital Signature Algorithm)

#### ✅ 사용 사례:
- 전자서명, SSL/TLS 인증서, 전자정부 공개키 기반구조(PKI)

---

### 3.3. 해싱(Hashing)

- 입력 데이터를 고정된 길이의 해시값으로 변환하는 **단방향 함수**
- 복호화 불가능, 입력 데이터의 **무결성 검증**에 사용
- **동일한 입력은 항상 동일한 해시값**, **다른 입력은 완전히 다른 결과**

#### ✅ 대표 알고리즘:
- SHA-256, SHA-512 (Secure Hash Algorithm)
- SHA-1 (더 이상 안전하지 않음)
- MD5 (보안 취약, 사용 권장되지 않음)

#### ✅ 사용 사례:
- 비밀번호 저장, 파일 무결성 검사, 디지털 서명 해시 생성

---

## 4. 하이브리드 암호 시스템 (Hybrid Cryptosystem)

대칭키와 비대칭키 암호화를 **혼합하여 사용하는 구조**로, 현실에서 가장 많이 사용되는 방식이다.

> 예: HTTPS 통신
> - 비대칭키(RSA)를 이용해 세션 키(AES 키)를 안전하게 교환
> - 이후 대칭키(AES)로 빠른 암호화 통신 수행

이러한 구조는 보안성과 성능을 모두 만족시키는 방식이다.

---

## 5. 기타 정보보호 관련 기술

| 기술 | 설명 |
|------|------|
| **전자서명 (Digital Signature)** | 송신자의 신원 확인 및 메시지 무결성 검증을 위한 기술 |
| **인증(Authentication)** | 사용자 혹은 시스템의 신원을 검증하는 절차 |
| **접근제어(Access Control)** | 사용자 권한에 따라 자원 접근을 제어 |
| **암호 프로토콜(Cryptographic Protocols)** | 키 교환, 인증, 무결성 검증 등 다양한 암호학적 목적을 위한 통신 규약 (예: SSL/TLS, IPsec) |

---

## 6. 요약 비교표

| 항목 | 해싱 | 대칭키 암호화 | 비대칭키 암호화 |
|------|------|----------------|------------------|
| 복호화 가능 여부 | ❌ 불가능 | ✅ 가능 | ✅ 가능 |
| 키 구조 | 키 없음 (단방향) | 동일 키 사용 | 공개키 / 개인키 |
| 속도 | 매우 빠름 | 빠름 | 느림 |
| 주요 목적 | 무결성, 비교 | 기밀성 | 기밀성, 인증 |
| 사용 예 | 비밀번호 저장, 무결성 | 파일 암호화, TLS | 전자서명, 인증서 |

---

> 📌 **결론**:  
> 정보보호는 암호화, 해싱, 인증, 접근제어 등 다양한 기술을 기반으로  
> **기밀성, 무결성, 가용성**이라는 원칙을 실현하며,  
> 실제 환경에서는 대칭/비대칭키를 혼합한 **하이브리드 암호체계**가 널리 사용됨.
