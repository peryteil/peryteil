# 🔐 해싱 / 대칭키 / 비대칭키 암호화 알고리즘 정리

## ✅ 1. 전체 비교표

| 구분 | 해싱(Hash) | 대칭키(Symmetric) | 비대칭키(Asymmetric) |
|------|-------------|--------------------|------------------------|
| 🔍 목적 | 데이터 무결성 확인<br>(복호화 불가) | 데이터 암호화/복호화 | 데이터 암호화/복호화 + 인증 |
| 🔑 키 | 없음 (단방향) | 1개의 동일한 키 사용 | 공개키 + 개인키 (서로 다른 2개) |
| 🔁 복호화 가능 여부 | ❌ 불가능 | ✅ 가능 (같은 키) | ✅ 가능 (공개/개인키 조합) |
| 💡 사용 예시 | 비밀번호 저장, 디지털 서명 검증 | 파일 암호화, VPN, TLS 내부 전송 | 이메일 암호화, 전자서명, 공개키 기반 인증 |
| ⏱ 속도 | 매우 빠름 | 빠름 | 느림 |
| 🔐 대표 알고리즘 | SHA-256, SHA-1, MD5(비권장) | AES, DES, RC4 | RSA, ECC, DSA |

---

## ✅ 2. 해싱 (Hashing)

- **입력값 → 고정된 길이의 해시값으로 변환**
- 단방향 변환이므로 복호화 불가능
- 입력값이 조금만 바뀌어도 완전히 다른 결과 출력
- **주 용도**: 비밀번호 저장, 무결성 검증, 디지털 서명

### 🔐 대표 알고리즘
- SHA-256
- SHA-1 (구버전)
- MD5 (보안 취약, 비권장)

---

## ✅ 3. 대칭키 암호화 (Symmetric Encryption)

- 하나의 **공통된 키로 암호화와 복호화 모두 수행**
- 속도가 빠르고 효율적
- 단점: **키 분배** 문제

### 🔐 대표 알고리즘
- AES (권장)
- DES (구버전)
- RC4

### 💡 사용 예
- 파일 암호화
- VPN 트래픽 암호화
- HTTPS 통신 시 세션 암호화

---

## ✅ 4. 비대칭키 암호화 (Asymmetric Encryption)

- **공개키(Public Key)**로 암호화하고, **개인키(Private Key)**로 복호화
- 또는 그 반대로 전자서명에 사용
- 보안성과 인증에 강력하지만 속도는 느림

### 🔐 대표 알고리즘
- RSA
- ECC (Elliptic Curve)
- DSA

### 💡 사용 예
- 전자서명
- 이메일 암호화
- 인증서 기반 SSL/TLS 통신

---

## ✅ 5. 실제 사용 예 (혼합 방식)

> 대부분의 실제 보안 시스템은 **대칭 + 비대칭 + 해싱**을 함께 사용함.

### 🌐 예: HTTPS 통신
1. 비대칭키(RSA)로 세션 키 교환
2. 세션 키로 대칭키(AES) 암호화 수행
3. 사용자 인증용 비밀번호는 해싱(SHA-256)해서 저장

---

## ✅ 6. 요약

| 항목 | 해싱 | 대칭키 | 비대칭키 |
|------|------|--------|----------|
| 🔁 복호화 | 불가 | 가능 (같은 키) | 가능 (공개-개인키) |
| ⏱ 속도 | 가장 빠름 | 빠름 | 느림 |
| 🔐 용도 | 무결성, 인증 | 빠른 암호화 | 키 교환, 서명, 인증 |

---

> 📌 **요약:**  
> 해싱은 단방향 무결성 검사,  
> 대칭키는 빠른 암호화/복호화,  
> 비대칭키는 키 교환과 인증에 사용됨.
