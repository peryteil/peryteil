# 데이터 교환 포맷 및 시리얼라이징 이해

# JSON, XML, YAML 비교

JSON, XML, YAML은 모두 **데이터를 표현하고 교환**하기 위한 포맷입니다. 이 문서는 이 세 가지 포맷의 차이점을 **형식, 특징, 사용 용도** 측면에서 비교합니다.

---

## ✅ 1. 기본 비교 표

| 항목 | **JSON** | **XML** | **YAML** |
|------|----------|---------|----------|
| 전체 이름 | JavaScript Object Notation | eXtensible Markup Language | YAML Ain’t Markup Language |
| 형식 | 키-값 쌍의 구조 (JavaScript 객체 유사) | 태그 기반 마크업 구조 | 들여쓰기 기반 구조 |
| 가독성 | 중간 (괄호 많음) | 낮음 (태그 중복) | 높음 (간결한 들여쓰기) |
| 파일 확장자 | `.json` | `.xml` | `.yaml`, `.yml` |
| 주석 지원 | ❌ 없음 | ✅ 있음 (`<!-- 주석 -->`) | ✅ 있음 (`# 주석`) |
| 스키마 검증 | JSON Schema 사용 | XSD, DTD 사용 | 제한적 |
| 파싱 속도 | 빠름 | 느림 | 중간 |
| 표현력 | 중간 | 높음 (속성, 태그 중첩 등) | 낮음~중간 |
| 대표 사용처 | 웹 API, 설정 파일, 모바일 앱 | 웹 서비스(SOAP), 문서 중심 시스템 | CI/CD, 설정 파일 (Kubernetes, Docker 등) |

---

## ✅ 2. 동일 데이터 예시

### JSON
```json
{
  "name": "홍길동",
  "age": 30,
  "hobbies": ["독서", "운동"]
}
```

### XML
```xml
<person>
  <name>홍길동</name>
  <age>30</age>
  <hobbies>
    <hobby>독서</hobby>
    <hobby>운동</hobby>
  </hobbies>
</person>
```

### YAML
```yaml
name: 홍길동
age: 30
hobbies:
  - 독서
  - 운동
```

---

## ✅ 3. 언제 무엇을 사용하면 좋을까?

| 상황 | 추천 포맷 |
|------|-----------|
| API 통신 (REST 등) | ✅ JSON |
| 복잡한 데이터 구조 필요 (문서형 데이터, SOAP 등) | ✅ XML |
| 설정 파일 (Kubernetes, Docker, GitHub Actions 등) | ✅ YAML |
| 사람이 직접 수정할 설정 (예: `.github/workflows/`, `.gitlab-ci.yml`) | ✅ YAML |
| 빠르고 간단한 파싱이 중요할 때 | ✅ JSON |

---

## ✅ 요약

- **JSON**: 구조가 간단하고 속도 빠름 → API 통신, 웹 앱에 적합
- **XML**: 표현력 강하고 태그 기반 → 복잡한 문서 구조 표현에 유리
- **YAML**: 가독성 뛰어나고 들여쓰기 기반 → 설정 파일에 적합


# HTTPS와 SSL 인증서 기초

웹 보안의 기본은 HTTPS와 SSL 인증서를 이해하는 데서 시작합니다. 이 문서에서는 HTTPS와 SSL 인증서의 개념, 동작 방식, 필요한 이유에 대해 간단히 설명합니다.

---

## ✅ 1. HTTPS란?

- **HTTPS (HyperText Transfer Protocol Secure)**는 HTTP에 **보안을 추가한 통신 프로토콜**입니다.
- HTTPS는 데이터 전송 시 **암호화**를 사용하여, 외부에서 데이터를 가로채도 내용을 이해할 수 없도록 합니다.
- HTTP는 평문(암호화되지 않음)으로 데이터를 주고받지만, HTTPS는 SSL/TLS를 통해 암호화됩니다.

---

## ✅ 2. SSL/TLS란?

| 항목 | 설명 |
|------|------|
| **SSL (Secure Sockets Layer)** | HTTPS 보안 통신을 위한 초기 암호화 프로토콜 |
| **TLS (Transport Layer Security)** | SSL의 후속 버전. 현재 대부분의 브라우저는 TLS를 사용 |
| ✅ 참고 | 실제로 우리가 "SSL 인증서"라고 부르지만 대부분은 "TLS 인증서" |

---

## ✅ 3. HTTPS 동작 방식 (간단 요약)

1. 브라우저가 서버에 HTTPS 요청을 보냄
2. 서버는 **SSL 인증서**를 브라우저에 전달
3. 브라우저는 인증서를 검증 (신뢰할 수 있는 기관인지, 유효한지 등)
4. 브라우저와 서버는 **비밀 키 교환**을 통해 암호화 통신 시작
5. 이후 데이터는 **암호화되어 안전하게 전송**

---

## ✅ 4. SSL 인증서란?

- 사용자의 브라우저와 서버 간의 **암호화 통신을 보장**해주는 디지털 문서
- **CA(인증기관)**가 발급하며, 도메인 소유권을 검증함
- 주요 포함 정보:
  - 인증서 소유자 (도메인)
  - 공개키 (암호화에 사용)
  - 인증 기관 정보
  - 만료일

---

## ✅ 5. HTTPS를 사용해야 하는 이유

| 이유 | 설명 |
|------|------|
| 🔐 보안 강화 | 데이터 도청, 중간자 공격(MITM) 방지 |
| ✅ 신뢰성 | 브라우저에 "자물쇠 아이콘" 표시로 사용자에게 신뢰 제공 |
| 📈 SEO 가산점 | Google은 HTTPS 사이트에 검색 순위 가산점을 부여 |
| 💳 민감 정보 보호 | 로그인 정보, 결제 정보 등 민감한 데이터 보호 |

---

## ✅ 6. 무료 SSL 인증서

| 제공자 | 설명 |
|--------|------|
| **Let's Encrypt** | 가장 많이 쓰이는 무료 인증서 제공 기관 |
| Cloudflare | 자체 SSL 제공 (프록시 방식) |
| ZeroSSL | 이메일 기반 무료 인증서 발급 |

---

## ✅ 요약

- **HTTPS = HTTP + 보안(암호화)**
- **SSL 인증서**는 사이트와 사용자 간의 안전한 통신을 위한 디지털 문서
- 브라우저는 SSL 인증서를 검증하고, 안전한 키 교환 후 암호화 통신을 시작함
- 보안을 위해 모든 사이트는 HTTPS를 사용하는 것이 **사실상 필수**
