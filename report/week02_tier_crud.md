3-Tier Architecture란?
3-Tier Architecture(3계층 아키텍처)는 소프트웨어 애플리케이션을 세 가지 주요 계층, 즉 프레젠테이션 계층(Presentation Tier), 애플리케이션 계층(Application/Logic Tier), 데이터 계층(Data Tier)으로 분리하는 구조적 설계 패턴입니다. 이 구조는 각 계층이 논리적, 물리적으로 분리되어 독립적으로 개발, 운영, 확장될 수 있게 해줍니다.

프레젠테이션 계층 (Presentation Tier)
사용자가 직접 마주하는 계층으로, 주로 사용자 인터페이스(UI)를 담당합니다.
웹 브라우저, 모바일 앱, 데스크톱 애플리케이션 등에서 사용자와 상호작용하는 부분입니다.
HTML, CSS, JavaScript 등 클라이언트 측 기술이 주로 사용됩니다.

애플리케이션 계층 (Application/Logic Tier)
비즈니스 로직을 처리하는 계층입니다.
프레젠테이션 계층에서 받은 요청을 처리하고, 데이터 계층과 상호작용하여 필요한 데이터를 가공합니다.
Java, C#, Python 등 서버 측 언어 및 프레임워크가 활용됩니다.
미들웨어(Middleware), 백엔드(Back-end)라고도 불립니다.

데이터 계층(Data Tier)
데이터의 저장과 관리를 담당하는 계층입니다.
데이터베이스 관리 시스템(DBMS)이나 파일 시스템 등이 이 계층에 포함됩니다.
MySQL, PostgreSQL, MongoDB 등 다양한 데이터베이스가 사용됩니다.

3-Tier Architecture의 장점
유지보수 용이성: 각 계층이 분리되어 있어, 특정 계층만 수정하거나 확장할 수 있습니다.
확장성: 필요에 따라 각 계층을 독립적으로 확장(Scale-out/Scale-up)할 수 있습니다.
보안성: 프레젠테이션 계층과 데이터 계층이 직접 통신하지 않고, 애플리케이션 계층을 통해서만 데이터가 오가기 때문에 보안 위협을 줄일 수 있습니다.
독립적 개발: 각 계층이 별도의 팀에 의해 동시에 개발될 수 있어, 개발 속도가 빨라집니다.

계층(Tier)과 레이어(Layer)의 차이
계층(Tier):물리적 분리를 의미합니다. 예를 들어, 각 계층이 서로 다른 서버에서 동작할 수 있습니다.
레이어(Layer): 논리적 분리를 의미합니다. 같은 서버 내에서도 코드 수준에서 역할을 분리할 수 있습니다.

3-Tier Architecture 예시 (웹 애플리케이션 기준)
계층	          역할 및 예시
프레젠테이션 계층	웹 브라우저, HTML/CSS/JS
애플리케이션 계층	서버(예: Java, Node.js, Python)
데이터      계층   데이터베이스 서버(MySQL, MongoDB)

3-Tier Architecture는 웹, 모바일, 엔터프라이즈 등 다양한 애플리케이션에서 널리 사용되는 표준적인 구조입니다. 각 계층의 독립성과 역할 분담으로 인해, 대규모 시스템 개발과 유지보수에 특히 유리합니다.

CRUD 개념과 웹 흐름
CRUD 개념
CRUD는 데이터 관리의 네 가지 기본 동작을 의미하는 약어로, 각각 다음과 같이 해석됩니다.
Create (생성): 새로운 데이터를 추가하는 작업입니다. 예를 들어, 회원 가입 시 사용자 정보를 데이터베이스에 저장하는 것이 이에 해당합니다.
Read (읽기): 저장된 데이터를 조회하거나 읽어오는 작업입니다. 예를 들어, 게시판 목록을 불러오는 것이 이에 해당합니다.
Update (수정): 기존 데이터를 변경하는 작업입니다. 예를 들어, 게시글을 수정하는 것이 이에 해당합니다.
Delete (삭제): 데이터를 삭제하는 작업입니다. 예를 들어, 특정 게시글을 삭제하는 것이 이에 해당합니다.

이 네 가지 동작은 데이터베이스뿐만 아니라 파일 시스템, REST API 등 다양한 데이터 처리 시스템에서 핵심적으로 사용됩니다.

웹에서의 CRUD 흐름
웹 애플리케이션에서 CRUD는 주로 다음과 같은 흐름으로 동작합니다.
1. 클라이언트 요청
    사용자가 웹 브라우저에서 데이터를 입력하거나 요청(예: 게시글 작성, 목록 조회, 수정, 삭제)합니다.
2. 컨트롤러(Controller) 처리
    클라이언트의 요청이 서버의 컨트롤러에 도달합니다.
    컨트롤러는 요청을 분석하고, 필요한 경우 서비스(Service) 게층에 처리를 위임합니다.
3. 서비스(Service) 계층
    비지니스 로직을 처리하며, 데이터 접근 계층(DAO/Repository)과 컨트롤러 사이의 중간 역할을 합니다.
4. DAO/Repository 계층
    데이터베이스와 직접적으로 통신하여 CRUD 작업을 수행합니다.
5. 데이터베이스
    실제 데이터의 생성, 조회, 수정, 삭제가 이루어집니다.
6. 응답 반환
    처리 결과를 컨트롤러가 받아 클라이언트(웹 브라우저)로 다시 전달합니다.
    예를 들어, 게시글 작성 후 목록 페이지로 이동하거나, 수정/삭제 결과를 알리는 메시지를 보여줍니다.

웹 CRUD 흐름 예시 (게시판 기준)
단계	            설명
1. 요청	         사용자가 게시글 작성/조회/수정/삭제 요청
2. Controller	요청을 받아 Service 계층에 전달
3. Service  	비즈니스 로직 처리, DAO/Repository 호출
4. DAO/Repo 	데이터베이스에 CRUD 쿼리 실행
5. DB	        데이터 생성/조회/수정/삭제
6. 응답	         결과를 Controller → 클라이언트로 반환

REST API와 CRUD
웹에서 REST API를 사용할 경우, HTTP 메서드와 CRUD 동작은 다음과 같이 매핑됩니다.
CRUD동작	HTTP 메서드     예시 URL
Create	    POST	      POST/users
Read	    GET	          GET /users, /users/{id}
Update	    PUT/PATCH	  PUT /users/{id}
Delete	    DELETE	      DELETE /users/{id}

전체적인 웹 CRUD 데이터 흐름 요약
1. **클라이언트(브라우저/앱)**에서 HTTP 요청(POST/GET/PUT/DELETE) ->
2. **서버(Controller)**가 요청 수신 ->
3. Service에서 비즈니스 로직 처리 ->
4. DAO/Repository 에서 DB CRUD 쿼리 실행 ->
5. DB에서 데이터 조작 ->
6. 결과를 클라이언트에 반환
