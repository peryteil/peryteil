## 숙제는 이 폴더에 한다.


### 폰노이만 아키텍처 동작 원리
폰 노이만 아키텍처는 현대 컴퓨터의 기본 구조로, 프로글매 명령어와 데이터를 동일한 메모리(주기억장치)에 저장하고, 중앙처리장치(CPU)가 이를 순차적으로 읽어와 실행하는 방식입니다.

주요 구성 요소
중앙처리장치(CPU): 명령어 실행과 데이터 처리를 담당합니다.
메모리: 명령어(프로그램)와 데이터가 함께 저장됩니다.
입출력장치: 외부와의 데이터 교환을 담당합니다.
버스: CPU, 메모리, 입출력장치를 연결하는 통로 역할을 합니다.

동작 원리: 명렁어 실행 사이클
폰 노이만 구조의 컴퓨터는 다음과 같은 순서로 동작합니다.
1. 명령어 가져오기(Instruction Fetch, IF)
CPU가 메모리에서 현재 실행할 명령어를 읽어옵니다.
2. 명령어 해석(Instruction Decode, ID)
읽어온 명령어가 어떤 작업을 의미하는지 해석합니다.
3. 피연산자 인출(Operands Fetch, OF)
명령어 실행에 필요한 데이터를 메모리에서 가져옵니다.
4. 명령어 실행(Instruction Execute, EX)
해석된 명령어에 따라 연산을 수행합니다.
5. 결과 저장(Write Back, WB)
연산 결과를 메모리나 레지스터에 저장합니다.
6. 인터럽트 체크
외부나 내부에서 발생한 인터럽트가 있는지 확인합니다.

이 과정은 프로그램 카운터(PC)가 다음에 실행할 명령어의 메모리 주소를 기억하고, 명령어를 순차적으로 처리하는 방식으로 반복됩니다.

폰 노이만 구조의 특징
-프로그램 내장 방식: 프로그램(명령어)과 데이터가 같은 메모리에 저장되어, 소프트웨어만 바꾸면 다양한 작업을 수행할 수 있습니다. 하드웨어를 직접 변결할 필요가 없습니다.
-순차적 처리: 명령어를 한 번에 하나씩 순차적으로 처리합니다.
- 명령어와 데이터의 구분 없음: 명령어와 데이터가 동일한 메모리 공간을 공유합니다. CPU는 이를 구분해 처리합니다.
- 버스 병목 현상: 명령어와 데이터가 같은 버스를 통해 이동하므로, 동시에 처리하지 못해 속도 병목이 발생할 수 있습니다.

예시와 비유
주방에 비유: CPU는 요리사, 메모리는 도마, 저장장치는 주방 창고에 비유할 수 있습니다. 요리사는 도마(메모리)위에 올려진 레시피(명령어)와 재료(데이터)를 사용해 요리를 진행합니다.

요약
폰 노이만 아키텍처를 명령어와 데이터를 같은 메모리에 저장하고, CPU는 이를 순차적으로 읽어 실행하는 구조입니다. 이로 인해 프로그램 변경이 쉽고 범용성이 높지만, 명령어와 데이터가 같은 경로를 사용해 속도 병목이 발생할 수 있습니다.

### HTML 시멘틱 태그의 역할
시멘틱 태그(Semantic Tag)는 HTML 요소가 담고 있는 콘텐츠의 의미와 역할을 명확하게 정의하는 태그입니다. 단순히 화면에 내용을 보여주는 것뿐만 아니라, 그 내용이 웹 문서에서 어떤 역할을 하는지 명시적으로 나타탭니다.

시멘틱 태크의 주요 역할
-콘텐츠의 의미 부여
각 태그가 담당하는 역할이 명확해집니다. 예를 들어, <header>는 머릿글, <nav>는 내비게이션, <footer>는 바닥글, <article>은 독립적인 글, <section>은 주제별 구역 등으로 사용됩니다.
-웹사이트 구조의 명확화
문서의 구조화 흐름을 논리적으로 구분하여, 개발자와 사용자 모두가 웹페이지의 구조를 쉽게 파악할 수 있습니다. 이는 유지보수성과 가독성을 높여줍니다.
-접근성(Accessibility)향상
스크린리더 등 보조기기가 시멘틱 태그를 통해 콘텐츠의 구조와 역할을 인식할 수 있어, 시각장애인 등 다양한 사용자가 웹사이트를 더 쉽게 이용할 수 있습니다.
-검색엔진 최적화(SEO)
검색엔진이 시멘틱 태그를 참고해 웹페이지의 주요 콘텐츠와 구조를 더 잘 이해할 수 있어, 검색 결과에서 더 높은 평가를 받을 수 있습니다.

### DOM(Document Object Model) 조사
DOM(문서 객체 모델)은 HTML 이나 XML 문서를 프로그래밍적으로 다룰 수 있도록 문서의 구조, 스타일, 내용을 객체 형태로 표현한 모델입니다. DOM은 웹 브라우저가 웹페이지를 이해하고, JavaScript와 같은 스크립트 언어가 웹페이지의 요소에 접근하거나 조작할 수 있도록 해주는 핵심적인 인터페이스입니다.
DOM의 구조와 특징
-트리 구조
DOM은 문서 전체를 트리(Tree) 자료구조로 표현합니다. 각 HTML 태그는 '노드(Node)'라고 불리며, 부모-자식-형제 관계를 가집니다. 예를 들어, <body> 태그는 <html>의 자식이고, <div>,<p> 등은 <body>의 자식이 됩니다.
-노드의 종류
DOM을 구성하는 노드에는 여러 가지가 있습니다.
요소 노드(Element Node):HTML 태그 자체
텍스트 노드(Text Node): 태그 내의 텍스트
주석 노드(Comment Node):HTML 주석 등
-객체 지향적 표현
DOM은 문서의 각 부분을 객체로 표현합니다. 따라서 JavaScript에서 객체처럼 각 요소에 접근, 수정, 추가, 삭제가 가능합니다.

DOM의 역할과 기능
-문서의 구조화
HTML이나 XML 문서를 계층적으로 구조화하여, 프로그래밍 언어가 문서의 각 부분에 쉽게 접근할 수 있게 합니다.
-동적 조작
JavaScript등 스크립트 언어를 통해 웹페이지의 내용을 동적으로 변경하거나, 요소를 추가/삭제, 스타일을 변경하는 등 다양한 조작이 가능합니다.
-API 제공
DOM은 다양한 프로퍼티와 메서드를 제공하여, 예를 들어 document.getElementById(), element.childeren, element.parentElement 등으로 요소를 쉽게 탐색하고 조작할 수 있습니다.

DOM의 활용 에시
-특정 요소에 접근:
let nav = document.getElementById('nav');
-자식 요소 조회:
console.dir(document.body.children);
-부모 요소 접근:
console.dir(element.parentElement);
-동적 요소 추가/삭제, 스타일 변경 등

DOM 의 표준
-W3C 표준
DOM은 W3C(World Wide Web Consortium)에서 표준화한 모델로, HTML DOM, XML DOM 등 다양한 문서 유형에 맞는 DOM이 존재합니다

요약:
DOM은 웹 문서를 트리 구조의 객체로 표현하여, JavaScript 등 프로그래밍 언어가 웹페이지의 구조, 내용, 스타일을 동적으로 조작할 수 있게 해주는 인터페이스입니다. DOM의 존재 덕분에 웹페이지는 정적인 문서가 아니라, 다양한 상호작용과 동적 변화가 가능한 애플리케이션으로 동작할 수 있습니다.
